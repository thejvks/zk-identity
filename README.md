## The Idea

Standard identity systems store your data. ZK-Identity doesn't.

```
Traditional:  "Are you over 18?" → Show your ID → They store your birthdate ❌
ZK-Identity:  "Are you over 18?" → Generate proof → Submit proof → ✓ (nothing revealed)
```

The math guarantees it. Not a promise. Not a policy. **A proof.**

## Quick Start

### 1. Clone & Install

```bash
git clone https://github.com/thejvks/zk-identity
cd zk-identity
npm install
```

### 2. Configure environment

```bash
cp .env.example .env
# Fill in:
#   PRIVATE_KEY=          your deployer wallet private key
#   RPC_URL_MUMBAI=       your RPC endpoint
#   POLYGONSCAN_API_KEY=  for contract verification
#   LLM_API_KEY=          for AI reputation scoring
```

### 3. Compile & Test

```bash
npm run compile      # Compile Solidity contracts
npm test             # Run full test suite
```

### 4. Compile ZK Circuits

```bash
# Install Circom
npm install -g circom

# Compile circuits
npm run circuit:age
npm run circuit:unique

# Trusted setup (for production, use a real ceremony)
npm run circuit:setup
```

### 5. Deploy

```bash
npm run deploy:mumbai   # Polygon Mumbai testnet
npm run deploy:polygon  # Polygon mainnet
```

### 6. Run the Frontend

```bash
npm run frontend:dev    # http://localhost:3000
```

## How the ZK Proof Works

### Age Verification (AgeVerifier.circom)

```
Private inputs:  birthYear = 1995
                 salt      = 0x3f7a...  (random)

Public inputs:   minAge       = 18
                 currentYear  = 2025
                 nullifierHash = Poseidon(birthYear, salt, 1)
                 commitmentHash = Poseidon(birthYear, salt)

Circuit proves:
  1. commitmentHash == Poseidon(birthYear, salt)     // you know the birthYear
  2. nullifierHash  == Poseidon(birthYear, salt, 1)  // nullifier is correct
  3. currentYear - birthYear >= minAge               // you are old enough

Nothing on-chain reveals birthYear. Ever.
```

### Nullifier Design

Each nullifier is scoped to a claim type. The same credential used for:
- Age proof → `Poseidon(secret, salt, 1)`
- Uniqueness proof → `Poseidon(secret, salt, contextId)`

Cross-app tracking is **cryptographically impossible**.

## Smart Contracts

### ZKIdentity.sol

```solidity
// Verify a ZK proof and mint an identity attestation
function verifyAndAttest(
    bytes32 nullifierHash,
    bytes32 commitmentHash,
    uint256 claimType,
    uint256 reputationScore,
    uint256[2]    calldata proofA,
    uint256[2][2] calldata proofB,
    uint256[2]    calldata proofC
) external;

// Check if an address has a verified claim
function hasClaim(address user, uint256 claimType) external view returns (bool);

// Self-revoke an attestation
function revokeAttestation(bytes32 nullifierHash) external;
```

### Claim Types

| ID | Claim | Proof |
|---|---|---|
| `1` | Age ≥ N | AgeVerifier circuit |
| `2` | Unique Human | UniqueHuman circuit |
| `3` | Credential | (extensible) |

## AI Reputation Oracle

The `ReputationOracle.sol` stores AI-computed scores anchored to ZK nullifiers — no wallet addresses, no personal data.

**Scoring signal examples (all anonymous):**
- Wallet activity age (months)
- Protocol diversity count
- Governance participation
- ENS / GitHub attestations

The off-chain AI oracle computes a score from 0–100, signs it with an authorized oracle key, and submits it on-chain. The nullifier links the score to the identity without revealing whose identity it is.
